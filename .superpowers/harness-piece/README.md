# Banc de la pièce G6 (mode d'emploi)

1. Prérequis : `playwright-core` installé HORS dépôt (`npm i playwright-core` dans `%TEMP%\pw-g6`, ou `PW_DIR=<dossier>`) ; Chrome `C:/Program Files/Google/Chrome/Application/chrome.exe`.
2. Serveur : `npx vite --config .superpowers/harness-piece/vite.config.ts` (port 5183, `strictPort`).
3. Pièce : `http://127.0.0.1:5183/.superpowers/harness-piece/piece.html?style=<StyleId>&h=<heure>&meteo=soleil|nuages|pluie|neige&pet=chat|chien|robot&scene=<nom>&t=<s>&w=1440` (`w` = largeur de la pièce rendue ; `t` fige l'horloge ; `rush=<ms>` budget de peinture par image tant qu'un repli est affiché ; `nostore=1` sans mémoire de l'appareil) ; `window.done` quand plus aucun `[data-sprite-fallback]` ET que la file du registre est vide (lecture en mémoire, peinture, encodage) ; vérifié à chaque image (rAF), pas par minuteur.
4. Planche : `planche.html?kind=<kind|a,b|all>&style=<StyleId>&res=1&cell=190` : kinds × 8 angles rendus par le moteur seul (`cell` = côté d'une case en px ; au-delà de 190 le dessin monte jusqu'à ×4 pour juger le détail ; `angles=2,6` pour ne rendre que ces angles, en très grande case).
5. Captures : `node .superpowers/harness-piece/shot.mjs <url-de-base> <dossier> "<requête>"...` (un PNG par requête ; attend `window.done`, 30 s, `TIMEOUT=<ms>` pour allonger).
6. Mesure : `node .superpowers/harness-piece/perf.mjs "<url>" [secondes]` : CPU ×4 (`CPU=<n>` pour changer). **Chronomètre retenu : depuis le premier `want()` du registre** (`window.__t0`, posé par le BenchRegistry) jusqu'à `window.doneAt` ; le temps depuis le chargement de la page est affiché entre parenthèses pour mémoire (il compte la transformation des modules par Vite, qui varie d'une passe à l'autre). Enchaîne : 1re visite (profil neuf, mémoire de l'appareil vide), régime établi (images/s), 2e visite (rechargement : la mémoire IndexedDB est gardée ; `SECOND=0` pour la sauter). Affiche aussi la peinture par sprite (dont l'encodage), le cache et la mémoire de l'appareil (`window.__spriteStats`, `__spriteStats.timeline()` = chaque demande et l'instant où son image est prête).
6 bis. Mesure en production (React construit, comme l'appli) : `npx vite build --config .superpowers/harness-piece/vite.prod.config.ts` puis `npx vite preview --config .superpowers/harness-piece/vite.prod.config.ts` (port 5184) et `perf.mjs "http://127.0.0.1:5184/.superpowers/harness-piece/piece.html?..."`. Le serveur de développement (5183) reste la référence de comparaison avec les tâches précédentes ; la production donne l'ordre de grandeur réel (tâche 4b : deux fois plus rapide à la 1re visite).
7. Publication : `node .superpowers/harness-piece/publish.mjs <dossier-de-png> <sous-dossier>` : copie dans `Wikimasters-g6-captures/g6/<sous-dossier>/`, met à jour `g6/README.md`, commit, push, affiche le lien (branche `captures/g6-piece`).
8. `scene=<nom>` (rock, nap, hide, scratch, brush, tree, egg) : **branché à la tâche 15** (moteur de vie du mobilier). Aujourd'hui le nom est seulement exposé (`window.__scene`) et l'animal suit son plan normal ; `pet=` pose bien l'animal (RoomView + `usePetSim`).
9. La pièce de `fixtures.ts` (`benchRoom(style)`) : 48 colonnes, étagère garnie, canapé, lampadaire arc, rocking-chair, pouf, bureau + écran + lampe, arbre à chat, monstera, palmier, fenêtres, décors muraux, tapis (lanterne en papier incluse, dans une zone dégagée). Les règles de pose du dépôt (`canPlace`, `canHangRect`) sont vérifiées par `tests/content/furniture-sprite-bench.test.ts` (famille scene-piece).
10. Pièges : la peinture est menée par tranches à chaque image (budget élargi tant qu'un repli est affiché, 6 ms sinon), donc le temps jusqu'à `done` dépend de la cadence d'images ; le banc tourne avec React en mode développement (serveur Vite), plus lent que l'appli construite ; à CPU ×4 le fil principal est saturé pendant la cuisson (un `setTimeout(0)` peut attendre plusieurs secondes). Voir les rapports des tâches 4 et 4b.
